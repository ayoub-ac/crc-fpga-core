# Synthesis comparison report

> **Unverified estimates.** The figures in this file have not been confirmed by a recorded, reproducible synthesis run or by hardware measurement. Treat every LUT, FF, BRAM, DSP, Fmax, throughput, latency and power figure here as an unverified estimate. Run `make synth_report` with your own toolchain to get real numbers.

Intended to be generated by `make synth_report`; the figures below are
unverified estimates, not a recorded run. Numbers are meant as
post-synthesis, pre-place-and-route. Vendor flows (Vivado / Quartus) usually pack
tighter than the open-source flow, so the Yosys numbers should be read
as upper bounds.

The synthesised configuration is `crc_top` with default parameters
(CRC-32 Ethernet, WIDTH=32, REFIN=REFOUT=1, XOROUT=0xFFFFFFFF). The
`WORD_PARALLEL=0` variant is reported here; the WORD_PARALLEL=1
variant adds three extra `crc_core` instances and is expected to roughly
triple the combinational LUT count (unverified estimate).

## Notes

* The dominant area is the per-byte combinational XOR network in
  `crc_core`. For WIDTH=32 this is roughly 32 + 8 = ~40 XOR2-equivalent
  gates plus a flat XOR reduction, which Yosys / Vivado map to a few
  dozen LUT4 / LUT6.
* Sequential cost is one CRC register (WIDTH bits), one byte counter
  (32 bits), the FSM (2 bits), and a registered output (WIDTH bits) -
  roughly 70-100 FF for the WIDTH=32 instance.
* No BRAM is used. The implementation is table-free; it is the
  Sarwate-style bit-serial transform unrolled to 8 bits combinationally.
* The optional `WORD_PARALLEL=1` variant chains four `crc_core`
  instances combinationally. It is expected to increase LUT count by
  roughly 3x and keep the FF count unchanged (unverified estimate). Useful for high-throughput pipelines
  (Ethernet MAC, NVMe-TCP).
* Vivado / Quartus rows are skipped automatically when those tools are
  not on PATH; with WebPACK / Web Edition installed they are intended to
  populate from a real `synth_design` / `quartus_sh` run. No CI runs
  this report.
